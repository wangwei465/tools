## Context

接口调试与编码转换两个模块都需要「对 JSON 按路径表达式取值」，但当前均无此能力。真实驱动场景是 ES 查询响应：结构深、数组套对象，目标字段常在 `hits.hits[0]._source.preConsultation.main.id` 这样的位置，靠折叠树逐层展开定位效率低。

本设计受以下既有约束支配：

- **模块边界**：`components/` 下各功能模块（api-client / compare / convert / redis / shell）之间**零跨模块引用**——代码验证无一例外，共享一律通过 `lib/` 层以 `@/lib/...` 别名进行。本设计不打破该边界。
- **结果约定**：`lib/convert/` 既有 `ConvertResult` 的 `ok()` / `err()` 约定（见 `lib/convert/result.ts`），所有转换器统一返回该结构而非抛异常。
- **隐私约束**：`encoding-toolkit` 规格已规定纯客户端计算、不出网、不写入 `app.db`。JSONPath 求值必须同样满足。
- **规模保护先例**：`lib/convert/regex.ts` 已确立 `MAX_TEXT_LENGTH` / `MAX_MATCHES` 上限保护模式，避免超大输入卡死界面。
- **当前布局刚性**：工作台为 `.apic-workbench` 内纵向排列的 savebar / `RequestPane` / `ResponsePane`；请求参数区 `.apic-subpane` 被 `max-height: 34vh` 锁死，响应区 `.apic-response` 以 `flex: 1` 吃掉剩余空间，比例不可调。且 `BodyEditor` 的 CodeMirror 高度写死为 `220px`，因此**仅放大容器并不会让编辑区变大**——这是拖动能否见效的关键连带点。
- **既有持久化机制**：`components/api-client/session.ts` 已用 localStorage 持久化 tab 会话（`api-tab-persistence` 规格），并确立了「持久化为增强项，不可用时静默降级」的处理原则。

## Goals / Non-Goals

**Goals:**

- 单一求值核心置于 `lib/`，接口调试与编码转换两个入口复用同一份逻辑与语义。
- 求值结果同时给出**命中值**与**命中路径**，路径可用于定位与复制。
- 非法 JSON、非法表达式、零命中三种结果彼此可区分，均以 `ConvertResult` 表达，不抛未捕获异常。
- 对超大文档与海量命中设置明确上限，超限给出提示而非静默截断或卡死。
- 求值全程浏览器端完成，不出网、不落库。
- 工作台请求区与响应区的高度比例可由用户拖动调整，调整结果跨会话保持，且任一区域不可被拖至不可用。

**Non-Goals:**

- 不做按 JSONPath 写入 / 修改 JSON（本能力只读提取）。
- 不做表达式历史或收藏的持久化（第一版仅会话内存）。
- 不做 JSONPath 表达式的自动补全与语法高亮。
- 不启用原生 `eval` 求值模式（见决策 2）。
- 不在 `components/` 之间共享 UI 组件（见决策 4）。
- 不做左右方向（侧边栏 / 主区）的拖动调整，本次仅处理请求区与响应区的上下比例。
- 不做布局预设、双击复位、拖动动画等增强交互。

## Decisions

### 决策 1：求值核心采用 `jsonpath-plus` ^10.4.0，而非 `jsonpath` 或自研

**选择理由**：官方 `resultType: 'all'` 直接返回 `{ path, value, parent, parentProperty }`，与「同时展示值与命中路径」的需求精确对齐，适配层极薄；语法覆盖完整（根 / 子节点 / 递归下降 / 索引 / 切片 / 通配符 / 过滤表达式），无需自行实现。

**备选与排除依据**（依据 npm 官方 advisory 端点查询结果）：

| 候选 | 当前安全公告 | 排除理由 |
|---|---|---|
| `jsonpath@1.3.0` | 无 | 依赖 `esprima@1.2.5`（2014 年版本）+ `static-eval` + `underscore`，上游维护停滞；「无公告」更可能反映关注度低而非实际安全 |
| 自研受限子集 | 不适用 | 零依赖零攻击面，但要覆盖过滤表达式就等于自写表达式求值器——而这正是 `jsonpath-plus` 两次 RCE 的成因，自研重蹈覆辙的概率不低于复用经过修复的上游 |
| **`jsonpath-plus@10.4.0`** | **无** | **选定**。历史有两条已修复公告：`GHSA-pppg-cpfq-h7wr`（`<10.2.0`，critical，CVSS 9.8）、`GHSA-hw8r-x6gr-5gjp`（`<10.3.0`，high，CVSS 9.8），均为 CWE-94 代码注入，成因在表达式求值路径。由决策 2 与风险缓解措施应对 |

### 决策 2：显式配置 `eval: 'safe'`，禁止 `'native'`

`jsonpath-plus` 的 `eval` 选项支持 `'safe'` / `'native'` / `true` / `false` / 自定义回调，默认 `'safe'`（自 9.0.0 起浏览器端默认安全求值，`preventEval` 已移除）。

- `'safe'` 使用最小脚本引擎，符合 CSP，是上游修复上述 RCE 后的推荐路径。
- `'native'` 使用 `eval` / `Function`，即历史漏洞的成因，**禁止使用**。
- `false` 会完全关闭 JS 执行，导致过滤表达式 `?(@.x > 1)` 失效，与需求冲突。

尽管 `'safe'` 已是默认值，仍**在调用处显式写出**：默认值属于上游可变行为，显式声明使其成为本项目的契约，同时向后续维护者标明此处是安全控制点，防止被随手改成 `'native'` 以「支持更复杂表达式」。

### 决策 3：`resultType: 'all'` 而非分两次求值

单次调用即取得值与路径，避免以 `'value'` 和 `'path'` 两次求值再按下标配对——两次求值不仅浪费，在结果集不稳定时还可能错配。

### 决策 4：共享止于 `lib/` 层，UI 各模块自行实现

- `lib/convert/jsonpath.ts`：求值、错误分类、上限保护，纯函数，无 React 依赖，两个入口共用。
- UI 层各写各的：编码转换侧需要「粘贴 JSON 输入框 + 表达式 + 结果」三段式；接口调试侧 JSON 来自当前响应（只读，无输入框），且需纵向填满响应区。二者布局约束不同，且跨 `components/` 引用会打破全项目零例外的模块隔离惯例。

结果列表的渲染会有少量重复，这是**刻意取舍**：模块边界的一致性优先于消除十几行 JSX 重复。若后续第三个入口出现，再将展示逻辑下沉。

### 决策 5：规模上限按 API 响应量级设定，不照搬正则测试器

`regex.ts` 的 `MAX_TEXT_LENGTH = 100_000`（约 100 KB）针对手工粘贴的测试文本；API 响应量级不同（ES 响应常达数百 KB），照搬会让工具在真实场景直接不可用。本能力单列常量：

- `MAX_JSON_LENGTH = 1_000_000`（约 1 MB）：覆盖绝大多数 API 响应；超限直接拒绝求值并提示，不做部分解析。
- `MAX_RESULTS = 1_000`：命中数上限。超限时展示前 1000 条并明示总命中数，而非静默截断——用户需要知道结果不完整。

瓶颈在结果渲染而非求值本身，故对文档大小相对宽松、对命中条数相对严格。

### 决策 6：错误分为三类，语义互不重叠

| 情况 | 返回 | 说明 |
|---|---|---|
| JSON 无法解析 | `err` | 提示 JSON 本身非法，附解析器原因 |
| 表达式非法 | `err` | 提示表达式语法错误，与 JSON 错误明确区分 |
| 表达式合法但零命中 | `ok`（空结果集） | 零命中是**正常结果**而非错误，界面提示「无匹配」 |

零命中归为成功是有意为之：用户以此确认「该路径确实不存在」，若归为错误会与「表达式写错了」混淆。

### 决策 7：接口调试侧仅对 JSON 响应启用

响应区新增页签的可用性与既有 `isJson`（按 `Content-Type` 判定）保持一致。非 JSON 响应下页签禁用并说明原因，与既有「二进制响应无法预览」的处理风格一致，避免对 HTML/纯文本求值产生无意义的报错。

### 决策 8：自研分隔条 + Pointer Events，只控制请求区高度一侧

**实现方式**：在 `.apic-workbench` 内、`RequestPane` 与 `ResponsePane` 之间插入分隔条，用 Pointer Events（`pointerdown` / `pointermove` / `pointerup` 配合 `setPointerCapture`）驱动。选用 Pointer Events 而非 `mousedown` + document 级 `mousemove`：指针捕获使拖动移出元素范围甚至移出窗口时事件仍然可靠送达，无需手工在 document 上挂载与清理监听，同时天然支持触控设备。

**备选与排除**：

| 方案 | 排除理由 |
|---|---|
| CSS `resize: vertical` | 原生零成本，但拖拽手柄固定在右下角、样式无法与暗色设计系统统一，且无法约束上下界、无法与响应区联动 |
| 引入 `react-resizable-panels` 等库 | 为单个分隔条引入运行时依赖，与项目一贯克制的依赖策略相悖；本场景所需逻辑约 60 行 |

**只控制一侧**：状态中只保存请求参数区的高度，响应区维持 `flex: 1` 自动占据剩余空间。若两侧都受控，需要额外保证「两者之和恒等于容器高度」，在窗口缩放时容易出现累积误差或裂缝。单侧受控让容器高度变化由 flex 自然吸收。

### 决策 9：`BodyEditor` 的编辑器高度由固定 `220px` 改为填满容器

这是拖动能否见效的**必要连带修改**，而非顺带优化：当前 CodeMirror 写死 `height="220px"`，放大 `.apic-subpane` 只会在编辑器下方留出空白，用户拖了却看不到编辑区变大，功能等同失效。

改动限于 Body 的 raw 分支：编辑器高度改为撑满容器，并由 `.apic-body-cm` 建立纵向 flex 使工具条固定、编辑区伸缩——与响应区 `.apic-resp-cm` 已采用的结构保持一致。Params / Headers / Auth 三个页签内容为表格，高度自适应，不作改动。

### 决策 10：拖动边界以「两区均保持可用」为准，高度持久化独立于 tab 会话

**边界约束**：请求区高度在 `[120px, 容器高度 - 160px]` 区间内钳制。下界保证参数页签与至少一行内容可见，上界保证响应区仍能显示状态行与页签——避免出现「拖到只剩一条边、必须刷新才能恢复」的死角。窗口尺寸变化时同样应用钳制。

**持久化位置**：使用独立的 localStorage 键，**不并入** `session.ts` 的 tab 会话。理由是关注点不同——tab 会话是用户数据（受 `api-tab-persistence` 规格管辖，随 tab 增删变化），布局高度是界面偏好（全局唯一，与打开哪些 tab 无关）。混入会让 tab 持久化的数据结构承担无关职责。

沿用 `session.ts` 已确立的原则：持久化属增强项，localStorage 不可用或读到非法值时静默回退到默认高度，不阻断工作台渲染。

### 决策 11：自建表达式前置校验（实施阶段发现，补充记录）

**问题**：实施时实测发现 `jsonpath-plus` **不校验表达式语法**，对非法输入采取宽容解析，且 `JSONPath.toPathArray()` 同样不抛错。12 个非法样本中仅 `$[?(@.x>1`（残缺过滤）真正抛出异常，其余均静默返回结果：

| 非法输入 | 实际行为 | 危害 |
|---|---|---|
| `$[`、`$.`、`$.a..b[` | 返回**根文档或上一层结果**，`len≥1` | 最严重——用户看到「成功」结果，误以为表达式有效 |
| `abc`、`a.b.c`、`$[0`、`$["x`、`$.a)` | 返回 `[]` | 被归为「零命中」，用户误判为「该路径不存在」而非「表达式写错了」 |
| `$..[?(@.` | 抛异常 | 唯一能被 try/catch 捕获的情形 |

两类误导都直接违反决策 6 确立的错误三分类语义——错误被伪装成了成功或零命中。

**决定**：在调用求值前自建校验，不通过则直接 `err`，不送入求值。规则为：

1. 表达式为空 → 提示输入（对齐 `regex.ts` 中 `if (!pattern) return err("请输入正则表达式")` 的既有做法）
2. 必须以 `$` 开头（JSONPath 规范的根标识）
3. 方括号 `[]`、圆括号 `()`、引号 `'` `"` 必须配对
4. 不得以 `.` 结尾（`$.`、`$..` 属残缺路径）

上述四条恰好覆盖实测到的全部 12 个非法样本。

**已知局限**：这是启发式校验而非完整的 JSONPath 语法分析，无法穷尽所有非法形式——仍可能有构造能绕过校验并被库宽容解析。选择启发式而非自研完整解析器，是因为后者等同于重新实现库的解析层，成本与风险都不成比例。校验规则集中在单个函数内，发现新的绕过样本时补充规则并追加回归用例即可。

## Risks / Trade-offs

- **[引入的库有两次 RCE 历史，均在表达式求值路径]** → 四重缓解：版本下限锁定 `^10.4.0`（高于全部已知受影响范围）；显式 `eval: 'safe'` 禁用原生求值；实施阶段将 `npm audit` 作为验收门禁；本决策记录在案，后续升级须复查公告。

- **[`'safe'` 模式的表达式能力弱于 `'native'`]** → 接受。复杂脚本表达式属低频需求，安全性优先；确有需要时应扩展受控的自定义回调，而非切换到 `'native'`。

- **[两处 UI 各自实现导致结果渲染逻辑重复]** → 刻意取舍（决策 4）。以模块边界一致性换取少量重复；出现第三个入口时再下沉抽取。

- **[新增运行时依赖，增加前端包体积与供应链面]** → 仅在两个页面按需引入，不进入全局 bundle；依赖链为 `jsep` 系列共 3 个包，规模可控。

- **[上限设定可能与个别超大响应冲突]** → 超限时明确提示当前大小与上限，而非静默失败；阈值集中为单一常量，调整成本低。

- **[零命中被用户误读为工具故障]** → 界面区分「无匹配」与「表达式错误」两种提示文案，不复用同一套错误样式。

- **[拖动时逐帧更新 React 状态导致卡顿]** → 拖动过程中只更新高度这一个数值，且不触发请求/响应内容的重新计算；若实测掉帧，再引入 `requestAnimationFrame` 节流，不预先复杂化。

- **[持久化的高度在小窗口下越界]** → 读取时与窗口变化时均执行同一套钳制逻辑，而非仅在拖动时钳制；保证任何来源的高度值都落在可用区间内。

- **[分隔条与 CodeMirror 的指针事件冲突]** → 分隔条为独立元素且使用指针捕获，拖动期间事件不会被编辑器截获；同时为分隔条设置足够的可点击高度，避免命中区域过窄难以拖动。
