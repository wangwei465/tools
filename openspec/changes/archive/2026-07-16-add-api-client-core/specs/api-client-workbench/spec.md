## ADDED Requirements

### Requirement: 独立接口调试工具页
系统 SHALL 提供独立的接口调试工具页 `/api-client`，并在全局导航（`TOOLS` 注册表）中提供入口，与数据比对工具相互独立。

#### Scenario: 从导航进入工具
- **WHEN** 用户在导航栏点击「接口调试」入口
- **THEN** 系统打开 `/api-client` 工具页并展示请求工作台

#### Scenario: 与比对工具互不影响
- **WHEN** 用户在接口调试工具中操作
- **THEN** 不影响数据比对工具的状态与既有 `/api/proxy` 行为

### Requirement: 多标签工作台
工作台 SHALL 支持同时打开多个请求标签（tab），用户可新建、切换、关闭标签；每个标签维护各自独立的请求与响应状态。

#### Scenario: 新建标签
- **WHEN** 用户点击「新建标签」
- **THEN** 系统创建一个「未命名请求」标签并激活，其请求为空白初始态

#### Scenario: 切换标签保留结果
- **WHEN** 用户在标签 A 发送请求得到响应后切换到标签 B，再切回 A
- **THEN** 标签 A 的请求内容与响应结果原样保留

#### Scenario: 关闭标签
- **WHEN** 用户关闭某个标签
- **THEN** 系统移除该标签；若其为当前激活标签，则激活相邻标签

### Requirement: 未保存改动标记
系统 SHALL 在标签上以标记（如 ●）标识该标签存在未保存改动（dirty）。

#### Scenario: 编辑后出现 dirty 标记
- **WHEN** 用户修改了某标签的请求内容
- **THEN** 该标签显示未保存改动标记

### Requirement: 发送与取消请求
工作台 SHALL 支持发送当前标签的请求，并在请求进行中支持取消。

#### Scenario: 发送请求
- **WHEN** 用户点击「发送」
- **THEN** 系统组装请求并经后端代理发起，进入「发送中」状态

#### Scenario: 取消进行中的请求
- **WHEN** 请求处于「发送中」时用户点击「取消」
- **THEN** 系统中止该请求，工作台回到可编辑状态且不展示响应
