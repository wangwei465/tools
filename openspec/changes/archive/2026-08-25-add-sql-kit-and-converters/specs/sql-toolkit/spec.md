## ADDED Requirements

### Requirement: 工具挂载与面板布局

SQL 工具 SHALL 作为独立菜单挂载到系统外壳，在 `Navigation` 的工具导航中出现，并以单页多标签的方式组织四个 SQL 处理面板，复用暗色设计系统；新增本工具 MUST NOT 改变任何既有工具的行为与路由。

#### Scenario: 从导航进入

- **WHEN** 用户点击导航中的「SQL 工具」入口
- **THEN** 系统在外壳内加载 `/sql-kit` 页面，展示面板标签栏，且全局导航保持可用

#### Scenario: 切换面板标签

- **WHEN** 用户点击某个面板标签（如「IN 列表」）
- **THEN** 系统展示该面板的输入/输出区，其余面板内容隐藏，当前标签明确高亮

#### Scenario: 切换标签不丢输入

- **WHEN** 用户在某面板输入内容后切换到其他标签，再切回该面板
- **THEN** 此前输入的内容与计算结果仍然保留

#### Scenario: 不影响既有工具

- **WHEN** SQL 工具被加入导航
- **THEN** 数据比对 / 生成签名 / 接口调试 / Redis管理 / 数据源 / 编码转换 / 加解密 的行为与路由均不受影响

### Requirement: 纯客户端与隐私约束

SQL 工具 SHALL 在浏览器端完成所有处理，MUST NOT 发起任何网络请求，MUST NOT 将输入内容持久化到 `app.db` 或任何后端存储。

#### Scenario: 处理不出网

- **WHEN** 用户在任一面板执行处理
- **THEN** 结果由客户端计算得出，不产生对后端 API 或第三方服务的请求

#### Scenario: 无持久化

- **WHEN** 用户输入内容并处理后刷新或离开页面
- **THEN** 输入内容不被写入后端库（仅存在于会话内存中）

### Requirement: SQL 日志参数填充

SQL 工具 SHALL 将含 `?` 占位符的 SQL 与参数列表合成为可读的完整 SQL：按参数声明的类型决定是否加引号，字符串内的单引号 SHALL 被转义；结果 SHALL 可一键复制。

#### Scenario: 分栏输入合成

- **WHEN** 用户在 SQL 输入区填入含 `?` 的语句，在参数输入区填入 `1(Integer), 张三(String)` 形式的参数列表并执行填充
- **THEN** 系统按顺序把参数代入占位符，数值类型不加引号、字符串类型加单引号，输出完整 SQL

#### Scenario: 整段日志自动拆分

- **WHEN** 用户一次性粘贴含 `Preparing:` 与 `Parameters:` 两行的日志片段
- **THEN** 系统自动识别并拆分出 SQL 与参数列表，无需用户手工分离

#### Scenario: 跳过非占位符的问号

- **WHEN** SQL 中的 `?` 出现在字符串字面量、单行注释或块注释内部
- **THEN** 系统 MUST NOT 将其视为占位符，参数按剩余的真实占位符顺序代入

#### Scenario: 数量不匹配硬报错

- **WHEN** 真实占位符数量与参数数量不一致
- **THEN** 系统展示错误提示并给出两侧数量，MUST NOT 输出部分填充的结果

#### Scenario: null 参数原样输出

- **WHEN** 参数列表中某项为 `null`
- **THEN** 对应占位符被替换为不加引号的 `null`

#### Scenario: 字符串内单引号转义

- **WHEN** 某个字符串类型参数的值本身含有单引号
- **THEN** 输出中该单引号被转义为 `''`，结果保持语法完整

#### Scenario: 明示用途边界

- **WHEN** 系统展示填充结果
- **THEN** 界面明确标注结果供人工核对与手动执行，不保证覆盖全部方言的字符串语法

### Requirement: SQL 格式化与压缩

SQL 工具 SHALL 提供 SQL 的美化（缩进与关键字换行）与压缩为单行两种输出，并允许用户选择 SQL 方言；无法解析的输入 SHALL 给出可读提示并保留原文，MUST NOT 丢失用户输入。

#### Scenario: 美化输出

- **WHEN** 用户输入单行长 SQL 并选择「美化」
- **THEN** 系统输出带缩进与关键字换行的多行 SQL

#### Scenario: 压缩为单行

- **WHEN** 用户输入多行 SQL 并选择「压缩」
- **THEN** 系统输出去除多余空白与换行的单行 SQL

#### Scenario: 切换方言

- **WHEN** 用户切换方言选项后重新格式化
- **THEN** 系统按所选方言的规则输出格式化结果

#### Scenario: 无法格式化时保留原文

- **WHEN** 输入无法被格式化
- **THEN** 系统展示可读提示且输出区保留用户原始输入，不清空、不抛出未捕获异常

### Requirement: IN 列表生成

SQL 工具 SHALL 把按行或分隔符切分的一列值转换为可直接粘贴进 `IN (...)` 的列表，支持带引号与不带引号两种形式，并支持去重、去空白与按指定大小分批。

#### Scenario: 生成带引号列表

- **WHEN** 用户粘贴多行文本值并选择「带引号」
- **THEN** 系统输出 `'a','b','c'` 形式的列表

#### Scenario: 生成数值列表

- **WHEN** 用户粘贴多行数值并选择「不带引号」
- **THEN** 系统输出 `1,2,3` 形式的列表

#### Scenario: 去重与去空白

- **WHEN** 用户启用去重且输入中含重复项与首尾空白
- **THEN** 输出中重复项只保留一个，各项首尾空白被去除，空行被忽略

#### Scenario: 分批切块

- **WHEN** 用户指定每批数量 N 且输入项数超过 N
- **THEN** 系统按 N 个一组输出多段列表，各段之间可清晰区分

#### Scenario: 值内引号转义

- **WHEN** 启用带引号且某个值本身含单引号
- **THEN** 该单引号在输出中被转义为 `''`

### Requirement: INSERT 语句生成

SQL 工具 SHALL 由 CSV 或 JSON 数组生成 `INSERT INTO` 语句，允许用户指定表名，并可选择「每行一条语句」或「单条多值」两种输出形式；输入非法 SHALL 给出可读提示。

#### Scenario: 由 CSV 生成

- **WHEN** 用户粘贴含表头的 CSV、填入表名并执行生成
- **THEN** 系统以表头为列名、以数据行为值，输出对应的 INSERT 语句

#### Scenario: 由 JSON 数组生成

- **WHEN** 用户粘贴对象数组形式的 JSON 并执行生成
- **THEN** 系统以对象键为列名、以键值为值，输出对应的 INSERT 语句

#### Scenario: 单条多值形式

- **WHEN** 用户选择「单条多值」输出形式
- **THEN** 系统输出一条 `INSERT INTO ... VALUES (...),(...),(...)` 语句而非多条独立语句

#### Scenario: 自定义分隔符与无表头

- **WHEN** 用户把分隔符切换为 Tab 或分号，或声明输入不含表头
- **THEN** 系统按所选分隔符切分；无表头时以列序号生成占位列名

#### Scenario: 类型与空值处理

- **WHEN** 某个值为数值、布尔或空
- **THEN** 数值与布尔不加引号输出，空值输出为不加引号的 `null`，其余按字符串加单引号并转义内部单引号

#### Scenario: 输入非法提示

- **WHEN** 用户粘贴的 JSON 非法，或 JSON 不是对象数组，或 CSV 各行列数与表头不一致
- **THEN** 系统展示可读的错误提示，说明具体原因，不产出半成品语句

#### Scenario: 表名缺失提示

- **WHEN** 用户未填写表名即执行生成
- **THEN** 系统提示表名必填，不输出语句
